## 将要改变什么

在保留现有一期功能和 API 的前提下，把 DataForge 整理成模块化单体：后端 API 按业务模块组合，前端拆分应用壳、路由、布局和页面模块，并建立统一设计 Token 与新的企业数据工作台视觉基础。

## 不改变什么

- 不实现向量化、索引、统一检索或 AI 应用运行时。
- 不改变现有业务数据模型、API 路径和 DataFlow Studio 挂载契约。
- 不拆微服务，不迁移 React，不重写 DataFlow WebUI。
- 不为未实现能力增加可点击的空功能。

## 主要风险

- 集中式 `App.vue` 拆分可能造成导航或状态回归；通过保持现有流程、增加真实路由并执行构建/场景检查控制。
- 后端路由拆分可能改变依赖初始化顺序；通过保留 `create_app` 作为唯一组合根并运行现有接口测试控制。
- 视觉重构范围容易扩张；本次只建设 Token、应用壳和现有页面基础，不提前设计后续业务。
